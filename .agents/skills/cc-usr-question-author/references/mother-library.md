# 母库登记与派生使用

母库只收录通过基础快照检查的 0-1 题。创建 0-1 批次时，系统为每道题建立一条 `mother_library` 记录；完成 GitHub 发布后，用 `set-repo` 同步 `repo_url`、40 位初始快照和本地 SHA。母库记录原始 Prompt、题目工作目录、来源批次和任务 ID，另外保留 `bugfix_ready`、`iteration_ready` 与 `defect_note`，方便选择合适的派生方向。

派生批次必须带 `author_mode: "derived"` 和一个 `mother_id`。出题前读取母项目的代码与文档，只用于理解已有边界，不读取任何目标模型会话、回复、轨迹或产物。派生题要有自己的 Prompt、题号、工作目录、Git baseline、仓库快照和质检记录；不要把母题 Prompt 原样复制成后续轮次。

每成功写入一条派生 `questions` 记录，事务内插入一条 `mother_usages`，并把母库 `use_count` 加一、更新 `last_used_at`。失败时整批回滚，不能留下虚假的使用次数。网页展示的使用次数来自 SQLite，不允许手工填写或凭估计修改。

小瑕疵不等于母项目失效。只要项目能构建、能启动、快照可访问且派生行为仍能独立描述，就可以将小问题作为 `Bug 修复` 题，或把改进方向作为 `Feature 迭代` 题，并在 `defect_note` 或派生说明中写清影响范围。只有构建/启动失败、仓库无法访问、快照与本地 HEAD 不一致，或问题让目标行为无法隔离时才阻塞。

Prompt 和记录说明必须像人工工作记录：使用具体观察和自然句子，避免连续套用同一语序、固定的“事实罗列+转折结论”结构、密集堆砌工具调用/测试数字或未经核对的架构判断。
